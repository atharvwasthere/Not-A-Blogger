# Not a Blogger redesign

This folder is the build spec for the redesign. Each numbered file is one pull request. They are written so they can be implemented without any other context: every colour value, HTML contract, data change and acceptance check is in here.

**Live prototype (public):** https://claude.ai/artifact/GUoQUqhpEVFgLJcZwyZ13j
It is a clickable copy of the redesigned site with the real posts: every route, search, the theme toggle, newspaper covers (toggle at the top), and a "Flows to try" panel. When this spec and the prototype disagree, this spec wins.

## Product rules (apply to every PR)

These came out of rejecting earlier drafts. They are the reason the spec looks the way it does.

1. **Say each thing once.** Before adding any element, ask: does the reader act on it, and is it already stated somewhere on the page? If either answer fails, cut it. No count strips ("4 figures · 3 references"), no summaries of what is further down the page.
2. **Only real data.** No "Most read" (there are no view counts), no Series section until a series exists, no invented metadata (stars, download counts, fetched previews).
3. **Keep the chosen styles.** Inter rounded chips, Geist Serif titles, Newsreader body, JetBrains Mono labels, the existing Subscribe animation. If something looks wrong, check whether the data is the problem before changing the style.
4. **Faint is decoration only.** The `faint` colour never carries text a reader needs (see the contrast table in PR 1).
5. **Brown means a label.** The `label` colour is for section labels (LATEST NOTE) and code keywords only, never links or body text.

Rejected on purpose, do not build: "On this page" / table of contents in any form, "Figures in this post", reading-progress bar, Most read, Series cards, stack keywords at the end of a post, topics on the landing page, About in the top nav, reader mode.

## Frontend architecture (applies to every PR)

Production structure, not one big route file. Values live in one place and components read them through hooks, not props passed down several layers.

```
frontend/src/
  styles/
    tokens.css          # every colour as a CSS variable, light + dark. The only place colour values exist.
  styles.css            # imports tokens.css, maps tokens into Tailwind (@theme inline), prose and code styles
  theme/
    ThemeProvider.tsx   # light/dark state, persistence, sets the class on <html>
    useTheme.ts         # const { theme, toggle, embedMode } = useTheme()
    topics.ts           # topic label, slug and tint helpers (maps to token names, never to hex values)
  features/
    settings/
      useSiteSettings.ts  # query hook for site-wide settings (covers on/off)
    blog/
      components/       # LatestNote, NoteRow, NoteCard, Print, CopyLinkButton, BasedOn, References
      hooks/            # useShare, usePosts
  shared/layout/
    SiteNav.tsx         # top nav (Notes · Topics · search · theme)
    IdentityRail.tsx    # left rail on browsing pages
    PhoneHeader.tsx     # compact header on phones
```

Rules:
- **Colour values appear only in `styles/tokens.css`.** Components use Tailwind classes generated from the tokens (`bg-paper`, `text-ink`, `text-soft`, `border-rule`, `text-label`) or `var(--…)`. No hex values in components, no `text-zinc-*` on public pages.
- **Shared state comes from hooks.** The theme comes from `useTheme()`, settings from `useSiteSettings()`, posts from the existing TanStack Query keys (`['posts']`, `['posts', slug]`). A component that needs the theme calls the hook itself; nothing threads `theme` through props.
- **One component per concern, named for what it renders.** A component file renders one thing; helpers that are not components go in `hooks/` or `theme/`.
- **Follow existing patterns.** TanStack Router file routes, TanStack Query `queryOptions`, `motion/react` for animation (copy the `SubscribeForm` choreography), the `Embed` TipTap node as the model for new editor nodes.

## Reader flows the redesign is built for

| # | Reader | Path |
|---|---|---|
| 1 | Someone shared a post with them (most readers) | Shared link → article → Copy link / References → home |
| 2 | Returning reader checking for something new | Home → Latest note → article |
| 3 | Wants more on one subject | Topics in the nav → topic page → article |
| 4 | Looking for one post | Search box in the nav or ⌘K → article |
| 5 | Wants the next post by email | Subscribe in the rail (end of the home page on phones) |
| 6 | Wants to know who wrote this | "About this site" in the rail |

## Commit rules

Commits are authored as the repository owner only, with no AI attribution or co-author trailers. Never commit scratch files or generated data. Run the full test suite before opening each PR and paste the results in the PR description.
